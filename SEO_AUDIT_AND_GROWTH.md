## Найдено и исправлено

1. Старый release-check не ловил второй canonical, повторное описание, односторонний hreflang и страницы без пути от главной. Новый verify-seo проверяет эти случаи и включён в build:pages, то есть CI и сборку Pages.
2. Проверка JSON-LD раньше ограничивалась синтаксисом. Теперь проверяются контекст/type, данные Article, порядок и цели BreadcrumbList, соответствие WebSite и SoftwareApplication реальному маршруту.
3. Убран неподтверждённый Organization publisher. Добавлены WebSite на главных и SoftwareApplication для реального Order Rescue без вымышленных оценок, отзывов, автора и коммерческих предложений. Такая минимальная разметка не обещает расширенный сниппет.
4. Добавлены необязательные PUBLIC_GOOGLE_SITE_VERIFICATION и PUBLIC_BING_SITE_VERIFICATION. Без выданных сервисами кодов теги не выводятся. DNS-подтверждение также доступно и не требует изменения приложения.
5. В предыдущем финальном аудите устранена блокировка JS поиска строгим CSP; добавлены безопасный JSON-LD, breadcrumb, Twitter Cards, contact и исправления структуры заголовков. Preview получает noindex в HTML и HTTP, sitemap отсутствует.
6. В README устранён локальный путь пользователя до публикации исходников; локальная неопубликованная история пересобрана без него.

Существующие механизмы сохранены: self canonical от SITE_URL, hreflang реальных переводов, sitemap только опубликованных маршрутов, robots со ссылкой на карту, slash-URL, 404 noindex. Параметры поиска не создают статических страниц и имеют canonical на /search/. Сейчас отдельная страница поиска индексируема как полноценный каталог двух статей и инструмента; при расширении поиска пересмотреть политику /search/ и параметров по фактическим данным, не плодить страницы запросов.

## Структура и масштабирование

Content Collections формирует маршруты из опубликованных Markdown, category из конечного справочника, переводы связывает translationKey. Пустые рубрики не генерируются. Статьи, практические инструкции и будущие сравнения могут использовать текущую коллекцию guides; не создавать /comparisons/ без материалов. Новые языки добавляются в конфигурацию и словари с реальными переводами; отсутствие перевода не должно вести hreflang на чужую главную.

При сотнях материалов: добавить пагинацию каталога/категорий; измерить размер поискового индекса; затем выбирать статический индекс с разбиением по языкам. Сейчас поиск включает только фактические 2 статьи и инструмент, JS gzip около 537 байт. Не добавлять тяжёлый поисковый сервис заранее.

## Скорость и доступность

Lighthouse не установлен в проекте; публичный сайт ещё не запущен. Полевая статистика LCP/INP/CLS отсутствует. Цели LCP ≤2.5 с, INP ≤200 мс, CLS ≤0.1 не считаются достигнутыми.

Размеры последней сборки до добавления JSON-LD: CSS gzip ~5.5 KB; Order Rescue + worker ~25.6 KB; поиск ~0.54 KB; SVG-иллюстрации <1 KB. Новый JSON-LD не добавляет исполняемого JS. Системные шрифты, размеры изображений, кеш immutable для хешированных ресурсов сохранены. 182 прежние проверки геометрии не заменяют измерение реальных устройств или WCAG-аудит.

После публикации: Lighthouse mobile для обеих главных, Google-статьи, поиска и инструмента; сохранить дату, браузер, throttling, URL и отчёт. INP измерять в полевых данных при достаточном трафике; лабораторный TBT не называть INP. Не добавлять preload/lazy-loading вслепую без обнаруженного узкого места.

## Search Console и Bing — после HTTPS

1. После активации demandlab.com.ua установить SITE_URL=https://demandlab.com.ua в Pages Production/Preview и GitHub Variables, пересобрать. Проверить canonical, reciprocal hreflang, sitemap и redirects со старого pages.dev. Не включать preview в карту сайта.
2. Google Search Console: добавить Domain property demandlab.com.ua, получить индивидуальный TXT и внести в реально обслуживающую DNS-зону. Не удалять запись после подтверждения. Альтернатива URL-prefix: добавить точный HTTPS origin и использовать выданный HTML tag (только значение content в PUBLIC_GOOGLE_SITE_VERIFICATION) с новой сборкой. Не придумывать токен.
3. Подтвердить владение, отправить /sitemap.xml, проверить главную и две статьи через URL Inspection: доступность, выбранный canonical, разрешение индексирования. Запрос индексирования не гарантирует включение или позиции.
4. Bing Webmaster Tools: добавить сайт, подтвердить через доступный сервисом DNS/файл/meta (PUBLIC_BING_SITE_VERIFICATION) либо импортировать уже подтверждённый Search Console после отдельного согласия на интеграцию. Отправить sitemap и проверить Site Scan.
5. Сейчас сайт не добавлен и владение в этих сервисах не подтверждено. Рекламные идентификаторы отсутствуют; реклама выключена. About/Contact/Privacy есть, но реальный канал связи ещё нужен. Одобрение AdSense не гарантируется.
